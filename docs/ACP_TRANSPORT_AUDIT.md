# ACP transport audit

Checked on Linux on 2026-09-30 against the [official ACP registry](https://agentclientprotocol.com/get-started/registry). The registry verifies that an agent advertises authentication in its ACP handshake. That does not establish that a particular account can finish a turn, that the adapter preserves the vendor's native sessions, or that it carries every ClikCode control.

ClikCode catalogs 29 harnesses. Twenty-one now prefer ACP for a new ordinary chat. Existing vendor sessions retain the transport that created them; the structured CLI remains available when an ACP agent cannot carry a requested image, model, or reasoning setting. These are compatibility paths, not parallel guesses at the same session ID.

| Existing harness | Registry integration | Decision and evidence |
| --- | --- | --- |
| Claude Code | [claude-agent-acp](https://github.com/agentclientprotocol/claude-agent-acp) | Switched new chats to the official ACP adapter. Automatic adapter installation, a real prompt, and resume on the same ACP ID passed. Ask, auto, bypass, model, and effort use ACP session controls. Old CLI sessions stay on CLI. Model discovery keeps using Claude's own model table so an empty ACP session is not opened merely to list models. |
| Cursor Agent | [Cursor ACP](https://cursor.com/docs/cli/acp) | Switched to `cursor-agent acp`. Real prompt and resume passed. The ACP model list supplies the exact IDs; display names may resolve a CLI-style choice only when unique. Old CLI sessions stay on CLI. |
| Grok Build | [Grok ACP](https://github.com/agentclientprotocol/registry/blob/main/grok-build/agent.json) | Switched to `grok agent stdio`. Real prompt and resume passed. Its running session usage is converted to per-turn usage. Old CLI sessions stay on CLI. |
| Codex | [codex-acp](https://github.com/agentclientprotocol/codex-acp) | Retained ClikCode's direct Codex app-server client. The ACP adapter launches that same app server, so changing transports would add a process and translation layer without gaining a native protocol. The direct client already handles sessions, permissions, usage, and steering. |
| Google Antigravity | [official ACP server](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json) | Retained the vendor's structured CLI. The separately distributed ACP server passed `initialize` on Linux, but `session/new` requires its own authentication choice; it does not reuse the installed `agy` CLI login. Its official Linux archive is 318 MiB compressed and expands to about 1 GiB. No authenticated turn or cross-platform installer has been proved. |
| Amp | [community ACP wrapper](https://github.com/agentclientprotocol/registry/blob/main/amp-acp/agent.json) | Retained the vendor's structured CLI. The registry package is a third-party binary wrapper rather than Amp's own ACP entry point. Replacing a direct vendor path with an untested wrapper would not establish a cleaner integration. |
| Pi Coding Agent | [community ACP adapter](https://github.com/agentclientprotocol/registry/blob/main/pi-acp/agent.json) | Retained the vendor's structured CLI. The adapter passed `initialize`, but `session/new` refused the available account and requested terminal login. A turn and resume have not been verified. |

The official registry also includes agents outside ClikCode's catalog. A registry listing alone is not an integration: adding a selectable harness requires an install path on supported platforms, credential flow, model and permission controls, session lifecycle, and a real turn/resume check. New entries should be added on that evidence, not counted from the registry's headline list.

For the OAuth-capable ACP harnesses already in the catalog, see [ACP_OAUTH_VERIFICATION.md](ACP_OAUTH_VERIFICATION.md). Ten of the eighteen still need vendor sign-in, quota, subscription, or eligibility before a real ClikCode turn and resume can be checked. That access cannot be supplied by a transport change.
