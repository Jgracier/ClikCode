What the transcripts showed:

- ClikCode's model does not narrate: no text between tool calls in any run.
  Its visible output (tool arguments plus text) was the same size as
  Claude Code's (06: ~1.05k vs ~1.08k tokens' worth of characters); the
  rest of each harness's output count is thinking, which the Gateway runs
  adaptively, reports as `reasoning_tokens` (0-330 per step) and does not
  stream. `reasoning_effort: "none"` does not turn it off (a probe step
  still reported 243 reasoning tokens).
- Steps were the controllable cost. The read-before-edit guard forced a
  read step for files whose exact lines grep had already shown (03: the
  model read invoice.ts and the test only after its first edits, a fifth
  step). With the guard gone for edit_file/multi_edit, 03 took 4 steps in
  all four runs and edited invoice.ts and the test straight from grep.
- Output per step tracks characters emitted (~1.6 chars/token for JSON-
  escaped code), about 190 tok/s. The big step in 03 is the edits: per-
  occurrence edit_file calls cost ~1.9k tokens (0350, 11 calls); a single
  script costs ~0.9-1.0k (0353, 0355, as Claude Code's model does). The
  new `paths` option was not used in these runs (each file also needed a
  different import edit, so the model batched per file or wrote one
  script); the 03 gain comes from the dropped read step and from the
  model choosing one script in 2 of 3 runs.
- 06's remaining extra steps are judgment: a second, broader grep for
  "any form" of env access, and a look at the tests to check empty-string
  semantics. Claude Code's model made a similar second grep.

Left on the Gateway side (not the harness):

- Time to first token is 0.65-3.4 s per step against Claude Code's
  0.9-1.1 s step totals for small steps; task 01's whole gap is this (the
  model produced the same ~500 tokens in the same 4 steps).
- The first step of every run reads nothing from the prompt cache: the
  prefix is ~20k tokens, 49k characters of tool schemas, 27.7k of them the
  25 tools of ClikDeploy's MCP server; the system prompt (3.5k chars) holds
  the working directory, so only a cache breakpoint after the tools could
  be shared across conversations.
