Ledger, steps over 5k prompt tokens: before (0347-0355, 59 steps) vs after (0609, 12):
mean provider first token 1,676 -> 1,276 ms (p50 1,083 -> 1,055, max 5,600 -> 3,115);
steps with reasoning 19/59 -> 2/12, mean reasoning tokens 64 -> 19; share of the
prompt read from cache 75% -> 82%.

What each fix did:

- Thinking. `reasoning_effort: "none"` became thinking `disabled`, which Sonnet 5.5
  refuses with a 400 (attempt rows `invalid_request` + `retry_without_effort`); the
  retry ran the vendor default, adaptive at `high`. Now `none` is
  `thinking: {type: "between_tools"}` on Sonnet 5.5 (adaptive at `low` on models
  that always think), served on the first attempt. A session with no effort now
  sends `medium` for Sonnet 5.5 / Opus 5.5, as Claude Code 2.1.289 does; before it
  sent nothing and got `high`.
- Cache. The tools-only breakpoint (7bdf3f9) is live: the first step of 06 now reads
  18,663 of 20,218 tokens written by task 01 (0 before). A failed read of the
  account's caching choice used to be cached as "off": in 0523 three steps went out
  with no breakpoints at all (0 read, 0 written). Fixed (8190140).
- Gateway overhead. Warm steps: admission 6-38 ms, resolve 7-35 ms, credit hold
  0-3 ms. The first step on a fresh replica after a release: 128-291 / 738-1034 /
  867-1473 ms before, 52-194 / 81-210 / 3 ms after (boot warm of recent chains and
  callers, refresh-ahead while in use).
- Cost. Every step reports `usage.cost` + `cost_details.upstream_inference_cost`;
  no row needs the `*` list-price estimate any more.

Not the Gateway lane, and still in the numbers: the stall in 03 (0523, 0552, 0609)
is the primary app process stalling for ~20 s when task 03 opens its MCP session.
The MCP request takes 22-27 s, the database pool is exhausted ("Unable to start a
transaction in the given time"), Redis calls time out and `/api/health` takes 4.3 s.
ClikCode then starts without the ClikDeploy MCP tools (26 tools instead of 53), and
a Gateway step that lands on that process waits it out (`admissionMs` 14,850).
Gateway steps are spread `least_conn` over the app and the aigw replica, so half of
them can land on the primary.
